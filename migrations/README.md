# Миграции PostgreSQL

Используем pgx/v5 v5.10.0 и Goose v3.26.0, как в metrics_service.
SQL встроен в бинарник через go:embed: запуск не зависит от рабочей директории.
Connect проверяет доступность БД, применяет миграции и возвращает pgxpool.Pool.
HTTP-сервер запускается после миграций; при остановке пул закрывается.
Подключение ограничено 5 секундами, вся подготовка базы — 30 секундами.
Ошибки приложения не содержат строку подключения.

00001_initial.sql создаёт users, accounts, orders и withdrawals.
Логин и номер заказа уникальны; номер заказа — TEXT с сохранением ведущих нулей.
Ссылки на пользователей защищены внешними ключами. Допустимые статусы:
NEW, PROCESSING, INVALID, PROCESSED. Индексы поддерживают списки пользователя
и выборку незавершённых заказов. Время хранится в TIMESTAMPTZ.

Баллы хранятся в NUMERIC без фиксированного масштаба: дробная часть сохраняется
точно без молчаливого округления. Отрицательные и бесконечные значения, NaN
запрещены; сумма списания положительна. Арифметику Go выберем при реализации
баланса. Создание счёта вместе с пользователем и изменение баланса вместе с
историей должны выполняться транзакционно на следующих этапах.

withdrawals.order_number не ссылается на orders: номер покупки для списания
не обязан быть загруженным заказом для начисления. Повторные списания пока
не ограничены уникальностью: правило определим на этапе баланса.
Таблица sessions пока не нужна; механизм авторизации выберем на этапе пользователей.

Goose отслеживает применённые версии. Новую схему добавляем новой миграцией,
а не редактированием уже применённой. Down удаляет таблицы и их данные;
приложение автоматически выполняет только Up.

Проверки: go test ./... и go vet ./.... Для проверки реального PostgreSQL
задай TEST_DATABASE_DSN и выполни go test ./internal/storage -run Integration -v.
Тест создаёт отдельную схему с уникальным именем, проверяет ограничения,
повторный запуск миграций, сохранность данных после переподключения и Down/Up,
затем удаляет только свою тестовую схему. Нужны права CREATE SCHEMA.
